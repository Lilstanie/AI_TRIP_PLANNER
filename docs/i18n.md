# English and Chinese documentation

English | [中文](i18n.zh.md)

Ordinary Markdown pages under `docs/` have an English `name.md` and Chinese `name.zh.md` pair.
`AGENTS.md` and its `CLAUDE.md` alias remain instruction entrypoints, not translation pairs. Root and
package READMEs, Agent Notes, session logs and skills are outside the mandatory pairing scope.
The [decision note](../.agents/notes/implemented/process/2026-09-26-bilingual-docs-agent-experience.md)
records the scope and trade-offs.

## Updating a pair

When a person or coding agent changes either language, update the other in the same change. Either
side can author a fact. Translate changed paragraphs, list items or table rows; retain reviewed
wording elsewhere. Reconcile simultaneous changes against the owning code instead of choosing a
language automatically. Use the [translate-docs skill](../.agents/skills/translate-docs/SKILL.md).

The skill is guidance for a running agent. It does not monitor files, start a background job or call
a translation service when a person saves English text. Agents following `docs/AGENTS.md` synchronize
pairs as part of their work. A read-only check detects omissions and stale review records.

## Structure and terminology

Keep technical conditions, timing, exceptions, units and failures. Code fences, including code
comments and Mermaid diagrams, are byte-identical; inline identifiers remain unchanged. Keep
heading levels, list types and table shape, but not identical prose wrapping or physical line counts.
Chinese links use the Chinese counterpart when one is in scope. Explicit anchors on Chinese headings
retain original English fragments, so links reach the same section. Language-switch links are the
cross-language exception.

| English           | Chinese convention                           |
| ----------------- | -------------------------------------------- |
| workspace         | 工作区                                       |
| trip brief        | 行程需求                                     |
| itinerary         | 日程；保留代码字段 `itinerary`               |
| provider          | 数据提供方；具体适配器名称不翻译             |
| provenance        | 数据来源信息；保留代码字段 `source.kind`     |
| fallback          | 回退；保留代码枚举 `fallback`                |
| mock              | 模拟数据；技术模式名及代码枚举 `mock` 可保留 |
| whole-party total | 全体出行者的总额                             |
| snapshot          | 快照                                         |
| streaming         | 流式输出                                     |

Keep tool, schema, package and agent identifiers in English. An unclear technical term may stay
English with a short explanation; resolve its meaning before standardizing a new translation.

## Review records and verification

After reviewing a specific pair's meaning and structure, record its two SHA-256 hashes:

```bash
node .agents/skills/translate-docs/scripts/check-pairs.mjs --record docs/architecture.md
node .agents/skills/translate-docs/scripts/check-pairs.mjs
```

Records live in `.agents/translation-pairs.json`. A hash change on either side requires renewed
review; recording does not translate anything or prove semantic equivalence. The checker compares
headings, lists, tables, fenced blocks and document links, and rejects missing or orphaned pairs.
Only record paths actually reviewed. Never refresh hashes to hide an outdated counterpart.

Run the pairing command alongside `pnpm verify:docs`, `pnpm verify:protected`, formatting and
`git diff --check` for documentation changes. Pairing currently runs locally through agent workflow
instructions; it is not included in `pnpm verify:docs` or CI. Adding that integration requires an
explicitly authorized change to the protected root scripts or CI configuration.

For an authorized rename or deletion, handle both files and repair links. After removing both files,
remove the obsolete record explicitly:

```bash
node .agents/skills/translate-docs/scripts/check-pairs.mjs --remove docs/old-page.md
```

The checker does not allow removing a record while either document still exists. Frozen historical
records are outside this workflow.
