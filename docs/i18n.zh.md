# 中英文文档

[English](i18n.md) | 中文

`docs/` 下的普通 Markdown 页面采用英文 `name.md` 与中文 `name.zh.md` 配对。`AGENTS.md` 及其 `CLAUDE.md` 别名仍是指令入口，不建立翻译副本。根目录和各包的 README、Agent Notes、session logs 和 skills 不属于必须配对的范围。[决策记录](../.agents/notes/implemented/process/2026-09-26-bilingual-docs-agent-experience.md) 说明了这一范围和取舍。

<a id="updating-a-pair"></a>

## 更新一组文档

人或 coding agent 修改任一语言时，应在同一次改动中更新另一版。事实可以先在任一语言中编写。翻译变化的段落、列表项或表格行，保留其它已审核措辞。两版同时发生变化时，依据其所属代码协调内容，不自动选择某一语言。使用 [translate-docs skill](../.agents/skills/translate-docs/SKILL.md)。

skill 为正在运行的 agent 提供操作指导。它不会监听文件、启动后台任务，也不会在人保存英文文本时调用翻译服务。遵循 `docs/AGENTS.md` 的 agents 会把配对同步作为本次工作的一部分。只读检查负责发现遗漏和过期的审核记录。

<a id="structure-and-terminology"></a>

## 结构与术语

保留技术条件、时序、例外、单位和失败语义。代码块（包括代码注释和 Mermaid 图）逐字节一致；行内标识符不变。保留标题层级、列表类型和表格结构，不要求正文换行或物理行数完全相同。中文链接在目标属于配对范围时使用中文版。中文标题上的显式锚点保留原来的英文 fragment，使链接仍到达对应章节。语言切换链接是跨语言的例外。

| 英文              | 中文约定                                     |
| ----------------- | -------------------------------------------- |
| workspace         | 工作区                                       |
| trip brief        | 行程需求                                     |
| itinerary         | 日程；保留代码字段 `itinerary`               |
| provider          | 数据提供方；具体适配器名称不翻译             |
| provenance        | 数据来源信息；保留代码字段 `source.kind`     |
| fallback          | 回退；保留代码枚举 `fallback`                |
| mock              | 模拟数据；技术模式名及代码枚举 `mock` 可保留 |
| whole-party total | 全体出行者的总额                             |
| snapshot          | 快照                                         |
| streaming         | 流式输出                                     |

工具、schema、包和 agent 标识符保留英文。含义尚不明确的技术术语可以暂留英文并附简短说明；确立新的统一译法前，先确认其含义。

<a id="review-records-and-verification"></a>

## 审核记录与验证

审核一组文档的含义和结构后，记录两份文件的 SHA-256：

```bash
node .agents/skills/translate-docs/scripts/check-pairs.mjs --record docs/architecture.md
node .agents/skills/translate-docs/scripts/check-pairs.mjs
```

记录保存在 `.agents/translation-pairs.json`。任一文件的哈希变化，都需要重新审核；记录操作不会翻译内容，也不能证明两版语义一致。检查工具比较标题、列表、表格、代码块和文档链接，并拒绝缺失或无英文来源的配对。只记录实际审核过的路径，不要为了掩盖过期译文而刷新哈希。

文档改动时，在 `pnpm verify:docs`、`pnpm verify:protected`、排版和 `git diff --check` 之外运行配对命令。目前配对检查由 agent 工作流指令要求在本地执行，尚未纳入 `pnpm verify:docs` 或 CI。接入这些流程需要获得对受保护的根目录脚本或 CI 配置的明确修改授权。

获得重命名或删除授权后，处理两份文件并修复链接。删除两份文件后，显式移除旧记录：

```bash
node .agents/skills/translate-docs/scripts/check-pairs.mjs --remove docs/old-page.md
```

任一文档仍存在时，检查工具不允许移除记录。不可修改的历史记录不属于这一工作流。
