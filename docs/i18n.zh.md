# 中英文文档

[English](i18n.md) | 中文

`docs/` 下的普通 Markdown 页面采用英文 `name.md` 与中文 `name.zh.md` 配对。`AGENTS.md` 及其 `CLAUDE.md` 别名仍是指令入口，不建立翻译副本。根目录和各包的 README、根目录的 `GLOSSARY.md` 术语表、Agent Notes、session logs 和 skills 不属于必须配对的范围。[决策记录](../.agents/notes/implemented/process/2026-09-26-bilingual-docs-agent-experience.md) 说明了这一范围和取舍。

<a id="updating-a-pair"></a>

## 更新一组文档

人或 coding agent 修改任一语言时，应在同一次改动中更新另一版。事实可以先在任一语言中编写。翻译变化的段落、列表项或表格行，保留其它已审核措辞。两版同时发生变化时，依据其所属代码协调内容，不自动选择某一语言。使用 [translate-docs skill](../.agents/skills/translate-docs/SKILL.md)。

skill 为正在运行的 agent 提供操作指导。它不会监听文件、启动后台任务，也不会在人保存英文文本时调用翻译服务。遵循 `docs/AGENTS.md` 的 agents 会把配对同步作为本次工作的一部分。只读检查负责发现遗漏和过期的审核记录。

<a id="structure-and-terminology"></a>

## 结构与术语

保留技术条件、时序、例外、单位和失败语义。代码块（包括代码注释和 Mermaid 图）逐字节一致；行内标识符不变。保留标题层级、列表类型和表格结构，不要求正文换行或物理行数完全相同。中文链接在目标属于配对范围时使用中文版。中文标题上的显式锚点保留原来的英文 fragment，使链接仍到达对应章节。配对检查按位置核对：每个中文标题都要带上对应英文标题的 fragment，可以是紧挨在标题上方的显式锚点，也可以是与英文完全相同的标题文字。语言切换链接是跨语言的例外。

| 英文               | 中文约定                                     |
| ------------------ | -------------------------------------------- |
| workspace          | 工作区                                       |
| brief (trip brief) | 行程需求                                     |
| itinerary          | 日程；保留代码字段 `itinerary`               |
| provider           | 数据提供方；具体适配器名称不翻译             |
| provenance         | 数据来源信息；保留代码字段 `source.kind`     |
| fallback           | 回退；保留代码枚举 `fallback`                |
| mock               | 模拟数据；技术模式名及代码枚举 `mock` 可保留 |

| snapshot           | 快照                                         |

| Agent Lab          | 保留英文 Agent Lab                           |

| planning loop      | 规划循环                                     |
| conflict           | 冲突                                         |
| targeted revision  | 定向修订                                     |
| round              | 轮，如“第 2 轮”                              |

表中也给出了根目录 [GLOSSARY.md](../GLOSSARY.md) 中各术语的中文形式。术语在那里变化时，要同步修改这里以及用到它的页面。
这张表出现之前写成的页面，在下次因其他原因修改时再统一措辞。

行内代码在配对之间按其完整文本（含换行）排序后逐项比较。每个行内代码必须写在同一行内；标识符要么在两种语言里都用反引号标出，
要么都不标：只出现在一种语言里、或出现次数不同的行内代码会使检查失败。

工具、schema、包和 agent 标识符保留英文。含义尚不明确的技术术语可以暂留英文并附简短说明；确立新的统一译法前，先确认其含义。

<a id="review-records-and-verification"></a>

## 审核记录与验证

在仓库根目录运行配对检查：

```bash
node .agents/skills/translate-docs/scripts/check-pairs.mjs
```

检查工具比较标题、列表、表格、代码块、行内代码和文档链接，并拒绝缺失或无英文来源的配对。它还会把改动与基线比较（默认 `origin/main`，可用 `--base <ref>` 更改），范围从合并基点到工作区：英文页面有空白以外的改动时，对应的中文页面必须在同一改动中一并修改。只改中文的修正可以通过。不再保存哈希，因此并行分支修改同一页面时，不会在记录文件上冲突。修改中文文件不能证明译文经过审核；推送前请核对其含义。基线不可用时，检查会说明这一点，只做结构比较。

文档改动时，在 `pnpm verify:docs`、`pnpm verify:protected`、排版和 `git diff --check` 之外运行配对命令 `pnpm verify:pairs`。CI 会在 `verify-docs` 之后以 pull request 的基线运行它，因此只改英文页面、没有同步中文页面的 pull request 会失败。根目录脚本和 CI 步骤是经所有者明确批准后加入的。

获得重命名或删除授权后，处理两份文件并修复链接。不可修改的历史记录不属于这一工作流。
