# Trip home 动作栏

[English](trip-home-actions.md) | 中文

状态：已实现。

本设计扩展现有的 [Trip home](../workspace-ui.zh.md#layout)。该页面继续列出当前 Trip 的 Chat，
并读取 Trip 自己保存的 Plan。此次改动把五个行程动作移到右侧栏，打开任何动作时都不离开
Trip home。

<a id="layout"></a>

## 布局

桌面上选择 Trip 后进入 Trip home：中间是居中的主栏，右侧是动作栏。

| 区域   | 内容                                                                           |
| ------ | ------------------------------------------------------------------------------ |
| 主栏   | Trip 标题与事实、根据方案生成的 AI 建议、关联到该 Trip 的所有 Chat，以及输入框 |
| 右侧栏 | 五张动作卡片，下面是嵌入的 Trip 地图                                           |
| 覆盖层 | 所选动作的右侧抽屉；覆盖右侧栏，并保留主栏可见                                 |

中间区域可以从主页仪表板变成一段 Chat，右侧栏保持不动。打开 Chat 时，沿用现有可调整的
Chat／地图分栏比例；从 Chat 返回后恢复 Trip home。

<a id="chats-and-suggestions"></a>

## Chat 与建议

- Trip home 列出 `tripId` 等于当前 Trip 的所有 Chat。一个 Trip 可以有任意多个 Chat。
- 选择一条 Chat 后，中间区域从仪表板替换为该对话。动作卡片和地图仍留在右侧；返回按钮回到
  Trip home。
- 从 Trip home 输入框发送消息时，会创建一个关联该 Trip 的新 Chat，把消息带入该 Chat 并打开它。
- 建议根据当前 Trip 的 Plan 生成。选择建议时，通过与上文相同的新建或当前 Chat 流程发送提示。
- 旅客关闭建议后，在这个 Trip 的 Plan 改变之前都保持关闭。新 Plan 可以重新产生建议。

<a id="actions"></a>

## 动作

动作卡片按以下顺序显示。每张卡片打开对应抽屉；有数量时同时显示数量。

| 动作             | 抽屉内容                                                                                 | 交互                                             |
| ---------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Itinerary        | 与对话中相同的可编辑 Trip 视图，包含活动、航班、住宿、待保存编辑和 Undo                  | 原位编辑；选择某天后地图聚焦到该天               |
| Ideas            | 未安排的活动和餐厅建议                                                                   | 沿用现有行程编辑流程把项目安排到某天             |
| Bookings         | 航班、住宿，以及其他标记为已预订的行程项目                                               | 已预订项目独立分组，不按行程顺序排列             |
| Trip preferences | 该 Trip 的现有偏好编辑器                                                                 | 修改沿用现有保存和重新规划行为                   |
| Calendar         | 仅针对当前 Trip 的重新设计只读日历；日期格突出行程日期，以及停靠点、航班和住宿的当天活动 | 选择某天后打开聚焦于该天的 Itinerary，并聚焦地图 |

产品还没有真实的媒体模型，因此不加入 Media；动作集合也不加入 Receipts。

<a id="drawer-behavior"></a>

## 抽屉行为

- 桌面端抽屉从右侧滑入，覆盖动作卡片和地图，并保留 Chat 或 Trip home 主栏可见。
- 手机端使用同一个抽屉，全屏显示并从右侧滑入。
- 关闭按钮、Escape 和点击抽屉外部都会关闭抽屉，并把焦点返回打开它的动作卡片。
- 打开另一个动作会替换当前抽屉。Settings 和现有嵌套编辑器的优先级保持不变。
- 同时只打开一个 Trip 动作抽屉。
- 抽屉是带可见标题的带标签 dialog。内容保持键盘可达，不创建额外的页面历史记录。
- Itinerary 与对话右上角 Trip 共用最新 Plan、活动身份、选中天、待保存编辑和 Undo 记录。
  在任一入口修改或撤销后，另一入口、Calendar 和地图立即一致；只有航班或住宿的日期显示为
  已预订，而不是空闲日。

<a id="phone-layout"></a>

## 手机布局

Trip home 改为单列，顺序如下：

1. 标题与事实。
2. 根据方案生成的建议。
3. 五张动作卡片。
4. Chat。
5. Trip 地图。
6. 输入框。

主页面只有一个滚动区域，输入框位于列的末端并且可以到达。动作抽屉全屏显示，关闭和焦点规则
与桌面端相同。

<a id="boundaries"></a>

## 边界

- 保留现有 Trip home 入口、标题、事实、Rename 和 Delete 菜单、读取最新 Plan 的规则，以及
  Trip 与多个 Chat 的关联。
- 替换当前会跳到对话 Trip 面板、全局 Calendar 页面或 Preferences 编辑器的动作卡片。
- 增加 Ideas 和 Bookings 视图，不增加新的数据概念。
- 不把 Trip home 变成刷新后恢复的存储页面。
- 不加入 Media 或 Receipts。

<a id="acceptance"></a>

## 验收

浏览器 E2E 覆盖以下项目后才算完成：

- 至少有两个 Chat 的 Trip 会同时列出两条，并能打开所选的一条。
- 从 Trip home 发送消息会创建一个关联同一 Trip 的新 Chat。
- 五个动作卡片都在不离开 Trip home 的情况下打开对应抽屉。
- Trip 首页 Itinerary 与对话 Trip 显示相同活动、航班和住宿，并同步 Plan 编辑与 Undo。
- 桌面抽屉保留主栏可见；手机抽屉占满屏幕。
- 关闭按钮、Escape 和点击外部都会把焦点恢复到打开抽屉的卡片。
- 在 Calendar 选择日期会打开聚焦该天的 Itinerary，并聚焦地图。
- 建议会把提示发送到关联 Chat；关闭建议后，刷新仍保持关闭，直到 Plan 改变。
- 桌面、平板和手机布局在中英文界面下都没有横向溢出。
