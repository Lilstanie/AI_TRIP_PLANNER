# 手机工作区改版

[English](mobile-workspace-redesign.md) | 中文

状态：已实施，并通过 Fixture 浏览器流程验收。真实设备安全区、真机键盘覆盖层和真实供应商
不在该证据范围内。

<a id="confirmed-scope"></a>

## 已确认范围

用户要求大幅调整整个手机工作区，包括导航、聊天、地图、方案编辑和“我的”。优先服务出发前
规划：描述需求、查看生成的 Plan、在地图上查看地点、修订方案、保存 Trip；同时保证出行时方便
查看已保存的行程。

沿用现有 Liquid Glass、语义颜色和系统字体，重点调整信息层级、内容位置和交互方式。

<a id="confirmed-interaction-decisions"></a>

## 已确认交互决定

用户接受了 Q4–Q14 的推荐。

- **主导航：**聊天、地图、行程、我的。延续 #713，没有 Plan 时隐藏行程。轨迹从团队入口
  打开全屏视图，保留记录列表和详情检查器需要的空间。实施前以新的 Agent Note 替代原先的
  底栏入口决定；保留轨迹功能。
- **我的：**已保存的 Trip 为主要内容，最近聊天为次级列表。搜索位于顶部；账户和设置集中
  到一个入口；新建操作放在对应内容旁。
- **手动编辑：**手机保留日期、预算、Stop 和 Stop 顺序编辑。行程需求修改用底部面板，Stop 修改
  用该行上的小弹层。
- **地图与行程：**分别保留完整页面，共享选中的日期和 Stop。从行程查看地图时定位该 Stop，
  返回行程保留原先上下文。
- **聊天：**顶部紧凑行程摘要打开 Brief 详情，输入框固定底部。空白聊天最多显示两条示例，
  有消息后隐藏。
- **规划反馈：**聊天内展示已有规划阶段和专家状态；完成后显示简洁结果和查看更新方案的
  入口，保留用户当前所在标签。
- **失败处理：**首次规划失败保留用户输入；修订失败保留当前可读 Plan，显示明确错误，
  由用户主动重试。

<a id="implementation-evidence"></a>

## 实施证据

基线是 main 提交 `9343038bb5a136fca97a9bfdd3a9bea361515003`（#713）。

- `PhoneTabBar.tsx` 包含聊天、地图、行程和我的；没有 Plan 时隐藏行程入口。团队入口在完整
  手机面板中打开轨迹。
- `PhoneMine.tsx` 以已保存 Trip 为主要内容，聊天次之，并保留搜索、新建、数据模式与设置入口。
  打开已保存 Trip 会进入行程。
- 地图与行程共享选中的日期和 Stop。在任一视图选择 Stop，会在另一视图定位对应到访；修订
  保留仍有效的日期，只清空已删除的 Stop。
- 聊天显示紧凑的 Brief、空白聊天最多两条示例、实时专家进度，以及完成或失败反馈，同时保留
  当前标签。
- 行程需求编辑使用底部 sheet，Stop 编辑在该行上以弹层打开。未完成的行程需求输入
  跨 Tab 保留，关闭前会先确认；Stop 编辑在提交时生效且关闭时不再询问，失败修改保留已输入值，
  已有 Plan 使用明确的 Replan trip（重新规划行程）操作。
- 可重复的 Fixture 流程是 `apps/web/tests/e2e/` 下的 `phone-navigation`；`phone-shell --prod`
  验证集成后的生产手机外壳。

<a id="failure-inventory-and-acceptance-evidence"></a>

## 失败场景与验收证据

以下场景定义上述可重复浏览器流程的验收覆盖。

| 失败场景                                    | 必须观察到的结果                                  |
| ------------------------------------------- | ------------------------------------------------- |
| 用户在地图或我的页面时生成 Plan             | 行程入口出现，当前标签保持不变                    |
| 选择后续日期的 Stop，包含多天重复访问的地点 | 地图与行程对应同一天、同一 Stop，返回时保留上下文 |
| 空白聊天出现第一条消息                      | 示例退出，不遮挡消息与输入框                      |
| 首次规划失败                                | 用户输入仍可用，错误明确，主动重试入口可用        |
| 已有 Plan 后修订失败                        | 原 Plan 仍可查看，不被空方案覆盖                  |
| 从团队入口打开轨迹                          | 列表与详情使用完整视口，关闭后回到来源页面        |
| 我的出现搜索、长标题或密集操作              | 已保存行程仍是主要内容，聊天、新建与设置可达      |
| 手机键盘压缩视口                            | 焦点输入与发送／保存可见，输入结束后恢复底栏      |
| 视口跨过 520/521 px                         | 当前内容与未保存的编辑仍可访问                    |

按 [UI 验收规范](../../.agents/skills/ui-verification/SKILL.md) 覆盖 390 × 844、360 × 800
手机，375 px 密集控件、1440 × 1000 桌面及手机断点切换。检查中英文、键盘与焦点、溢出及相关
显示偏好。保留可重复的 E2E 产物和截图，记录精确版本、配置与断言；只有实际检查过真机，
才能声称验证了真机安全区与键盘。

<a id="confirmed-edge-cases"></a>

## 已确认边界场景

用户接受了最后一轮推荐：

- **Q11 — 选择恢复：**同一 Trip 修订后保留仍存在的日期，否则选最近的有效日期；删除的
  Stop 清空选中。打开另一 Trip 恢复它自己的浏览位置，没有有效记录时默认第一天。
- **Q12 — 未提交编辑：**切换标签保留行程需求编辑。关闭或返回会丢弃已修改的行程需求字段
  时，先询问继续编辑还是放弃；没有改动直接关闭。Stop 编辑不再询问：
  [即时行程编辑 Agent Note](../../.agents/notes/implemented/feature/2026-10-27-instant-itinerary-edits.md)
  对行程部分取代此答案。已应用的修改沿用当前保存语义。
- **Q13 — 编辑范围：**已有 Plan 的目的地、日期、预算等 Brief 更新继续触发重新规划，操作
  名称明确体现该结果。保留 Stop 编辑与自动保存；不增加整份 Trip 的保存／放弃事务，也不
  新增排程算法。
- **Q14 — 打开已存行程：**在我的点击已保存 Trip 直接进入行程，点击最近聊天进入聊天。
  这会有意改变手机当前打开已存 Trip 后进入聊天的行为。

导航与我的、地图与行程共享浏览、聊天规划反馈和编辑保护四个实施部分已经集成，并通过使用
Fixture 供应商的真实工作区界面共同验收。

  定义可读的记录卡片与触控区域；调整入口时仍需保留这些能力。
- #713 有意在生成 Plan 之前隐藏行程入口；如需反转，应明确记录新的设计决定。
- 延续当前手机断点、桌面和平板行为、编辑状态保留与账户数据，除非访谈确认修改理由。
- 使用[术语表](../../GLOSSARY.md) 中 Brief、Plan、Trip、Stop、Trajectory 的既有含义。

Fixture 验收不能证明真实供应商或真机键盘行为。
