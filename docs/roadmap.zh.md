# 产品路线图

[English](roadmap.md) | 中文

近期目标是可靠的单用户工作区：描述旅行、查看有事实依据的推荐、编辑计划、保存计划，
并在旅行途中使用它。

<a id="status"></a>

## 状态

状态以 2026-10-30 的 `main`（`8029779`）为准；当前行为见[工作区 UI](workspace-ui.zh.md)。

**已完成**

- LangGraph 规划工作流，包含五个 LangChain specialist 和定向修订。
- 单用户工作区：聊天、偏好、受控筛选器、详情卡片、加载和错误状态，以及空白聊天中的建议标签。请求不完整时，只针对第一个缺失的行程事实提出一个问题；起草计划期间，规划状态会持续推进。
- 按天排列的日程与联动地图：编辑立即生效并可撤销，停靠点可在当天或跨天拖动，也可拖到备选地点标签；每段路程都有交通时间，每次编辑后都会进行路线、时间和预算检查。行程可导出为文本和日历文件。
- 每个保存的行程都有 Trip home：行程事实、关联的聊天、可开启新关联聊天的输入框、一条情境建议，以及在行程地图旁打开的 Itinerary、Ideas、Bookings、Trip preferences 和 Calendar 面板。Your trips 把行程分为 Upcoming 和 Past，其 Calendar 以周视图和月视图显示选中的行程。
- Agent Team：旅客可以 @ 提及五位 specialist 中的任意一位，查看哪些正在工作，并打开 Trajectory 逐步查看每个 agent 的工作记录。
- 浮层表面使用液态玻璃材质；Trip 面板上的待处理徽标显示尚未解决的行程问题。
- 通过每次请求的 mock/live 开关访问实时数据：Google Places 提供事实依据、SerpApi 酒店和航班搜索、
  天气预报及气候依据。
- 可见的数据来源：每个提案都报告其数据属于实时、估算、mock、回退还是不可用。
- 存储：浏览器中保存聊天和旅行；配置后，Redis REST 存储中保存聊天轮次、偏好、计划、
  SerpApi 用量和缓存。
- 聊天中流式展示规划进度和思考 transcript（文本记录）。
- 账号（Clerk）：配置后须通过独立登录页登录，把聊天、行程和设置同步到 Neon Postgres。Settings 在桌面端于侧边栏旁打开，在较窄屏幕上以对话框打开；其中的旅行档案会预填新行程，已登录旅客的长期记忆会保存从聊天中记住的偏好。
- 520 px 及以下的手机布局：底部标签栏（Chat、Map、Trip、Mine）、底部面板和可安装的 Web 应用清单。
- 界面语言（英文或简体中文），在 Settings 中切换；每个行程有自己的显示货币（AUD、CNY、USD 或 JPY），方案本身仍以 AUD 计价。
- 航班和住宿：日视图把每个航班和每晚住宿显示为可展开为卡片的行；旅客可以改选 specialist 找到的其他航班或住宿，无需重新规划。
- 公开的 Agent Lab：固定东京 fixture 在无需提供方密钥的情况下，展示单 agent 轨迹、
  经过校验的计划和确定性指标，并与运行一轮、不做修订的五 specialist 策略，以及在预算紧张变体上做有界定向修订的策略做对比。
  已完成的运行可下载为带版本的产物，并在页面中离线回放。基准场景涵盖预算不可行的巴黎行程，以及城市间移动必须保持一致的东京与京都行程；故障实验室让五个已注册的故障（提供方超时、空结果、非法输出、supervisor 故障、修订停滞）走过同样的视图。实时运行只在部署启用时存在，并受并发和每小时限额约束，fixture 运行绝不可能触及提供方或模型。公开的实验室已经完整：四个视图（Run、Compare、Failures、Architecture），发布证据来自同一个端到端脚本。

**待完成**

1. 在部署环境中使用真实密钥，对实时提供方进行端到端验证。
2. 描述、编辑、保存和旅行的完整流程稳定后，提供旅行途中模式。

**以后，仅在需要时实施**

- 通过 Aviationstack 等专门提供方获取航班延误、登机口和运行状态。
- 通过 Travelpayouts 等提供方获取联盟库存或预订链接。

<a id="definition-of-done-for-the-mvp"></a>

## MVP 的完成标准

- 用户可以输入目的地、出发地、日期、旅行者、预算和偏好。
- 推荐有事实依据，并标注来源和时效性，包括实时、估算和 mock 提供方状态。
- 用户可以查看和编辑真实的详情卡片，而非原始 JSON。
- 编辑后，时间、路线和预算冲突可见。
- 刷新后，可从 Your trips 重新打开已规划的旅行。
- 提供方失败时，系统以可见且安全的方式降级，绝不悄悄替换成虚构价格。
- 合并前，类型检查、lint、现有 CI 测试套件和生产构建均通过。复杂的新行为通过 E2E 测试验证，
  并留下可重复执行、可审查的产物。
