# 产品路线图

[English](roadmap.md) | 中文

近期目标是可靠的单用户工作区：描述旅行、查看有事实依据的推荐、编辑计划、保存计划，
并在旅行途中使用它。

<a id="status"></a>

## 状态

状态以 2026-09-22 的 `main` 为准；当前行为见[工作区 UI](workspace-ui.zh.md)。

**已完成**

- LangGraph 规划工作流，包含五个 LangChain specialist 和定向修订。
- 单用户工作区：聊天、偏好、受控筛选器、详情卡片、加载和错误状态，以及从空白聊天开始的示例旅行。
- 可编辑时间线和 Google 地图，提供路线、时间和预算检查。
- 通过每次请求的 mock/live 开关访问实时数据：Google Places 提供事实依据、SerpApi 酒店和航班搜索、
  天气预报及气候依据。
- 可见的数据来源：每个提案都报告其数据属于实时、估算、mock、回退还是不可用。
- 存储：浏览器中保存聊天和旅行；配置后，Redis REST 存储中保存聊天轮次、偏好、计划、
  SerpApi 用量和缓存。
- 聊天中流式展示规划进度和思考 transcript（文本记录）。

**待完成**

1. 在部署环境中使用真实密钥，对实时提供方进行端到端验证。
2. 描述、编辑、保存和旅行的完整流程稳定后，提供旅行途中模式。

**以后，仅在需要时实施**

- 通过 Aviationstack 等专门提供方获取航班延误、登机口和运行状态。
- 通过 Travelpayouts 等提供方获取联盟库存或预订链接。

<a id="definition-of-done-for-the-mvp"></a>

## MVP 的完成标准

- 用户可以输入目的地、出发地、日期、旅行者、预算和偏好。
- 推荐有事实依据，并标注来源和时效性，包括实时、估算和 mock 提供方状态。
- 用户可以查看和编辑真实的详情卡片，而非原始 JSON。
- 编辑后，时间、路线和预算冲突可见。
- 刷新后，可从 Your trips 重新打开已规划的旅行。
- 提供方失败时，系统以可见且安全的方式降级，绝不悄悄替换成虚构价格。
- 合并前，类型检查、lint、现有 CI 测试套件和生产构建均通过。复杂的新行为通过 E2E 测试验证，
  并留下可重复执行、可审查的产物。
