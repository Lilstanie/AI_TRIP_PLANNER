# UI loop after PR #941: day-card strip fades before its scroll buttons

## What changed

- `apps/web/app/styles/chat/messages.css`: the day-card strip under a planned reply uses an
  `--edge-fade` width. It is 24px on touch screens and 52px with a mouse, wide enough to cover the
  32px scroll button and its 4px inset.
- `apps/web/tests/e2e/plan-days-scroll.e2e.mjs`: new check that the fade is at least as wide as the
  later-days button. The E2E now seeds the mock data setting; since live data became the default
  (TP-237) it waited 90s for a reply that a local run without keys never sends.

## Why

UI loop round 61 (2026-11-03, TP-348): the 24px fade was narrower than the 36px the button covers, so
card text ran at full strength under the button and was cut off.

## Validation

- `plan-days-scroll.e2e.mjs`: 51/51 after; on the old CSS 48/51 with
  `FAIL desktop: card text fades out before it reaches the later-days button {"fadeEnd":24,...,"button":{"left":860,...}}`.
