## Session summary

- Author: Claude, follow-up to the Stage 5.2 session log.

- Module(s): specialist model routing (`packages/agents/src/models.ts`), destination guide, dining, itinerary.
- Goal / requirement source: resolve the MiniMax HTTP 401 recorded as an open issue in `2026-09-09-codex-stage-5-2.md`.
- Root cause of the 401: MiniMax runs two independent account systems. The supplied credential belongs to the mainland-China site, but Stage 5.2 defaulted `MINIMAX_BASE_URL` to the international host `https://api.minimax.io/v1`. Keys are not interchangeable. Probing the credential gave 200 on `https://api.minimaxi.com/v1` and `https://api.minimax.chat/v1` (same site, legacy domain) and 401 `invalid api key (2049)` on `https://api.minimaxi.chat/v1` and `https://api.minimax.io/v1`. No GroupId is required.
- Second defect: fixing the endpoint alone did not restore model output. `withStructuredOutput(..., method: "functionCalling")` makes LangChain send a forced `tool_choice`, which MiniMax M2.7 silently ignores — it answers in prose with `tool_calls: null`, indistinguishable from an auth failure at the call site. `response_format: json_schema` is ignored the same way. With `tool_choice: "auto"` it emits a well-formed call.
- Third defect: both providers treat the tool schema's numeric constraints as advisory. MiniMax overran `maxItems` and returned an array field as a string; DeepSeek consistently overran the 400-character `summary` cap in the dining draft.
- Fourth defect: Next.js loads `.env.local` from `apps/web/`, not the repository root. That file held only DeepSeek credentials, so the web app fell back for guide and dining even after the root `.env.local` was populated.
- What was done: added `createRoutedStructuredInvoker` to `models.ts`. DeepSeek keeps `withStructuredOutput`; MiniMax binds the tool itself with `tool_choice: "auto"` and validates arguments against the same Zod schema. Both branches now retry once with the failure fed back through `withCorrection`. Restated every hard schema limit literally in the destination-guide and dining prompts, since both models follow prose limits more reliably than JSON-schema numerics. Defaulted `MINIMAX_BASE_URL` to the mainland-China host and documented the two-site key incompatibility.
- Routing decision: all three tasks now route to DeepSeek. MiniMax produced comparable drafts but took 15-25s per structured call; measured full page renders were 37/48/49/74/81s on MiniMax against 15/21/22/23s on DeepSeek. The MiniMax branch stays wired and working — flip `MODEL_ROUTING` to route back.
- Follow-up, page latency: the home page took 20-23s to paint. `apps/web/app/page.tsx` awaits `runOrchestrator(DEMO_BRIEF)` in a `force-dynamic` server component, so nothing rendered until the whole negotiation finished. Tracing the rounds showed the graph never converged: the day-4 time overlap recurred verbatim in rounds 2 and 3, and the budget overrun oscillated (29.25% -> 16.50% -> 25.25%). Root cause: a revising agent only sees its own proposal, and `detectConflicts` handed it the counterpart's clock times with no indication of who held them or what they were, so the itinerary agent guessed — in one round it moved an activity exactly onto the transport leg. `detectConflicts` now names the blocked window and its owner in the constraint ("on day 4 keep clear of 09:00-11:20, held by transport (Tokyo -> Kyoto)"). The graph now converges in round 2 with zero conflicts and no section left in `needs_you`. The plan render was additionally moved behind a `Suspense` boundary with a `WorkspaceSkeleton` fallback, so the shell streams immediately.
