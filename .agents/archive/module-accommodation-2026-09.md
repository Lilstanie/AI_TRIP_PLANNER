# C — 住宿与预算交接说明

Owner: YI QIAO。对应 README 的 C 分工。此版本使用虚构 Booking 数据，不进行预订或付款。

## 已实现

- `packages/tools/src/booking.ts`：经济、标准、舒适和不可免费取消的 Saver 四类酒店候选，以及按人数/往返计算的航班报价。
- `packages/agents/src/accommodation/`：日期校验、房间分配、分城市住宿查询、候选比较、选定方案计价、预算协商降价。
- `packages/orchestrator/src/budget.ts`：按美分汇总选定方案，计算未舍入的超支比例，分离协商与升级阈值。
- 三个相关包接入 Vitest，根目录 `pnpm test` 会实际执行测试；测试任务依赖上游包测试，避免 Booking 改动后错误复用 agent/orchestrator 测试缓存。

## 保持现有接口的实现约定

`packages/shared` 没有修改；agent 只通过 `ctx.tools.booking` 和 `ctx.mem` 调用工具和记忆。
以下是本分支的 mock 约定，供 A/B/E review，不代表已经完成团队确认：

| 项目     | 约定                                                                                       |
| -------- | ------------------------------------------------------------------------------------------ |
| 酒店价格 | `pricePerNightUsd` 是每间房每晚的 USD 价格，mock 假定包含税费                              |
| 房间容量 | 每间最多两人；默认 `ceil(groupSize / 2)` 间；单人单间模式使用 `groupSize` 间               |
| 住宿日期 | 入住日计费、退房日不计费；只接受真实的 `YYYY-MM-DD` 日期，至少一晚                         |
| 多城市   | 仅以 `&` 分隔城市，按给定顺序均分晚数，余数分给靠前城市；这是待 B 替换的行程假设           |
| 航班价格 | `priceUsd` 是所有乘客的总价；提供 `return` 时已含往返，不应再乘人数或乘二                  |
| 提案费用 | 每段住宿仅一个选中酒店进入 `items.estCost`；其他候选及报价放在 `assumptions`，不会重复计费 |
| 住宿预算 | 不擅自分配整个旅行预算；由 orchestrator 汇总各 agent 的费用后提出降本要求                  |

MemoryStore 中的偏好仍使用现有 `UserPreference` 格式：

| key                              | value                                      | 默认值   |
| -------------------------------- | ------------------------------------------ | -------- |
| `accommodation.roomAllocation`   | `shared` / `individual`                    | `shared` |
| `accommodation.minRating`        | `0` 至 `10` 的数字字符串（评分，不是星级） | `0`      |
| `accommodation.freeCancellation` | `true` / `false`                           | `false`  |

这些字段名需要 E 接入筛选或确认偏好写入流程。已确认偏好在所有协商轮次中保留。

## 选择与协商规则

1. 过滤无效报价和不满足已确认偏好的候选。
2. 首轮优先从评分至少 8/10 且可免费取消的候选中选择最便宜的；没有此类候选则选择符合已确认偏好的最低价。
3. 预算/费用 revision 选择符合已确认偏好的最低价候选。默认的评分/免费取消偏好可以让步，明确保存的偏好不能让步。方案正文会注明评分、位置和取消政策。
4. 现有 `cut accommodation cost by ~30%` 约束会被读取，结果说明是否达到目标；目标基于相同输入下重新计算的初始方案。后续轮次不会反复打折。
5. 降本不改变人数、日期或房间分配。没有更便宜方案时如实保留最低可行价格，是否继续协商/升级由 A 控制。

未支持的时间/地理 revision 保留初始方案并明确说明需要更新 brief，不宣称已经解决该冲突。
当前没有上一轮 proposal/版本作为输入，真实动态报价接入前需要与 A 对齐快照或版本语义。

## 预算规则

- 任何实际超支（`NEGOTIATION_OVERRUN_PCT = 0`）都会进入现有协商循环。
- 保留 `ESCALATION_OVERRUN_PCT = 10`：超过 10% 是预算升级阈值，恰好 10% 不触发这一条。
- 阈值在现有流程的最终评估阶段使用，不新增提前升级流程。K 轮后仍有任何未解决冲突，A 的现有逻辑仍会升级，即使超支不足 10%。
- 金额按美分汇总，百分比不提前取整，防止小额超支或略超 10% 被隐藏。负数/非有限费用及不足一美分的预算会报错。

| 阶段    |                                         住宿 | 交通 | 活动 |                总价 |
| ------- | -------------------------------------------: | ---: | ---: | ------------------: |
| 第 1 轮 |   Tokyo 标准 4×380 + Kyoto 标准 3×360 = 2600 | 1890 |  200 | 4690（超支 17.25%） |
| 第 2 轮 | Tokyo Saver 4×220 + Kyoto Saver 3×200 = 1480 |  700 |  200 |                2380 |

交通与活动仍是 B 的现有示例数据。预算改为 1200 时，第 3 轮仍超支，生成 escalation；预算为 2300 时，剩余不足 10% 的超支也不会被静默接受。
