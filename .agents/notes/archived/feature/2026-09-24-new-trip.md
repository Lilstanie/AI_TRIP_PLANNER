# Agent Note: New trip is a blank conversation opened on the Where editor

Status: implemented
Archived: 2026-09-24
Owner: repository owner (@HeadmasterEggy)

## Problem

The repository owner asked for New chat and New trip to be separate actions. The sidebar had one
accent New chat button, and every trip came out of a chat: a `TripRecord` in the workspace catalog
exists only once a plan does, because it stores that plan's snapshot, and its row shows the plan's
dates, total and status.

Mindtrip, observed read-only on 2026-09-24, keeps the two apart. New chat is a neutral pill below
the sidebar's sections; New trip is a button on the header of its Trips page, next to the trips it
adds to.

## Decision

New trip starts the same blank conversation New chat does, with two differences: the conversation is
named "New trip", and the Where editor opens with focus on Destination instead of the message input.
`startBlankChat(base, kind)` in `useWorkspaceController.ts` carries the difference; `newTrip` and
`newChat` are its two entry points.

- It reuses an untouched blank conversation, as New chat does, so alternating the two never stacks
  empty history entries. New chat renames a reused "New trip" back to "New chat".
- `upsertConversationDraft` keeps a conversation's existing title when an autosave passes none, so
  the "New trip" name survives typing. An explicit title still replaces it, and a renamed
  conversation keeps its name as before.
- The trip appears under Trips once a plan is produced, like any other.
- Expanded, New trip is a second pill directly below New chat, visible whichever list is shown,
  so both starts are always one click away (the owner asked for them to be separate, not hidden
  behind the Trips section as on Mindtrip's Trips page). The collapsed rail shows both actions as
  labelled icon buttons.

The catalog format, its version and `packages/shared` are unchanged, so stored catalogs load as
before.

## Alternatives considered

- **A placeholder `TripRecord` listed under Trips at once.** Rejected for now: `TripRecord.snapshot`
  and the trip row's dates, total and status all assume a plan, so it would need an optional snapshot,
  a catalog version bump with a migration, and a "not planned yet" state in every trip reader, for a
  row that holds nothing a blank conversation does not.
- **New trip as a second full-width button under New chat.** Rejected: two similar pills in a row
  read as one choice with two spellings, and Mindtrip puts New trip with the trips list.
- **Keep one button.** Rejected at the owner's request.

## Consequences

- Before its first plan, a new trip is visible only as a "New trip" row under Chats.
- New trip is not visible in the expanded sidebar while Chats is selected; Trips reveals it.
- If trips ever need to exist before a plan (named, dated, shared), the placeholder record above is
  the path, with its migration.
