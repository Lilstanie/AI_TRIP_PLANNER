# Agent Note: Stop visit progress

Status: implemented
Owner: issue #454

## Supersession check

[One day view](2026-10-08-one-day-trip-view.md) owns the existing stop menu and Undo.
This extends that menu without reversing its layout or editing decisions. The removed plan review
labels describe plan validity, not a traveller's progress at individual stops.

## Problem

Travellers cannot record which stops they visited or skipped without changing the itinerary.

## Decision

`ProposalItem.progress` is optional and accepts `planned`, `visited` or `skipped`. Missing or invalid
saved progress reads as planned. The existing stop menu changes it through `applyItemAction`, the
existing Undo restores the previous plan, and the catalog persists it with the item.

Progress changes only this field and the plan edit version. They bypass budget settlement to preserve
all stop fields, plan costs and schedule conflicts. They do not select another stop or reroute legs.
Restaurant suggestions keep their existing menu until scheduled as stops.

## Alternatives considered

- Separate visited/skipped flags allow contradictory states; one enum keeps the states exclusive.
- Removing skipped stops would discard their booking and cost information.
- Recomputing the plan after a progress change could change unrelated costs or conflicts.

## Consequences

Existing trips need no migration. Older clients ignore this optional field. The state is traveller
metadata; a new plan generated by chat may replace it along with the stop. No automatic next-stop
selection is introduced. Browser coverage checks desktop, phone, save/reopen and both languages.
